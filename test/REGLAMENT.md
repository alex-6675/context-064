# Регламент тестирования DOM-диагностики расширения (VK)

Цель: единообразно собирать и сохранять результаты диагностики страниц VK
перед адаптацией расширения под домен `vk.ru`.

## 1. Инструменты

- Браузер: **Microsoft Edge** (Chromium).
- Тестируемый скрипт: `test/vk_dom_diagnostic.js` (запускается в DevTools Console).

## 2. Запуск Edge без мешающих расширений

Чтобы сторонние расширения не влияли на результаты (не подменяли DOM/сеть),
Edge запускается с **чистым профилем** и загружается **только** целевое расширение
в режиме разработчика.

### 2.1. Чистый профиль (отключает все прочие расширения и синхронизацию)

```bat
:: Windows
msedge.exe ^
  --user-data-dir="C:	emp\edge-vk-test" ^
  --no-first-run ^
  --no-default-browser-check ^
  --disable-component-update ^
  --start-maximized
```

- `--user-data-dir` — отдельный профиль. В нём нет установленных расширений,
  поэтому сторонние расширения не мешают.
- `--no-first-run` — пропустить стартовые экраны.
- `--no-default-browser-check` — не предлагать сделать Edge браузером по умолчанию.
- `--disable-component-update` — меньше фоновой активности.
- `--start-maximized` — развернуть окно.

### 2.2. Загрузка ТОЛЬКО целевого расширения

Запустите чистый профиль (см. выше), затем в адресной строке:

```
edge://extensions
```

Включите «Режим разработчика» и выберите «Загрузить распакованное» -> укажите
каталог расширения (корень репозитория, где лежит `manifest.json`).

> ВАЖНО: `--disable-extensions` отключает **все** расширения, включая тестируемое.
> Для тестирования своего расширения его НЕ используйте — загружайте через
> `edge://extensions` в чистом профиле.

### 2.3. (Опционально) Автозагрузка расширения при старте

Можно добавить ключ автозагрузки распакованного расширения (только оно и будет):

```bat
msedge.exe ^
  --user-data-dir="C:	emp\edge-vk-test" ^
  --load-extension="C:\путь\к\репозиторию\context-064" ^
  --no-first-run --no-default-browser-check --start-maximized
```

## 3. Страницы для прогона диагностики

Отдельный прогон на каждом типе страницы (вёрстка VK различается):

1. Лента / стена (десктоп, `vk.ru`).
2. Страница поста с комментариями (десктоп).
3. Мобильная версия (`m.vk.ru`), если планируется её поддержка.
4. (если ещё открывается) старый `vk.com` для сравнения.

## 4. Сохранение ответа DevTools

Скрипт `test/vk_dom_diagnostic.js` в конце:

- кладёт полный объект результата в `window.__vkdiag`;
- пытается скопировать JSON-отчёт в буфер обмена (`navigator.clipboard.writeText`).

### 4.1. Способ А — копирование в буфер обмена (быстро, вручную)

1. После запуска скрипта в консоли появится строка
   «Отчёт скопирован в буфер обмена».
2. Вставьте текст в новый файл
   `test/results/<тип_страницы>_<YYYY-MM-DD>.json`.
3. Укажите в начале файла URL и дату (скрипт уже добавляет их в отчёт).

### 4.2. Способ Б — автосохранение файла отчёта из консоли (рекомендуется, страниц много)

Если консоль не позволяет записать файл напрямую, используйте сохранение из
вкладки **Console**:

- ПКМ по выводу объекта `window.__vkdiag` -> «Copy object» (или через выражение
  ниже) и сохраните в файл.

Либо выполните в консоли, чтобы скачать отчёт как файл:

```javascript
(() => {
  const data = JSON.stringify(window.__vkdiag, null, 2);
  const blob = new Blob([data], { type: 'application/json' });
  const a = document.createElement('a');
  a.href = URL.createObjectURL(blob);
  a.download = 'vkdiag_' + new Date().toISOString().slice(0, 10) + '.json';
  document.body.appendChild(a);
  a.click();
  a.remove();
})();
```

Файл сохранится в папку «Загрузки» браузера — затем перенесите его в
`test/results/`.

## 5. Правила именования отчётов

Формат имени файла:

```
test/results/<тип_страницы>_<YYYY-MM-DD>_<краткий_признак>.json
```

Примеры:

```
test/results/feed_2026-08-09_vkru.json
test/results/post_comments_2026-08-09_vkru.json
test/results/mobile_2026-08-09_mvkru.json
```

Признак домена: `vkru`, `vkcom`, `mvkru` — чтобы различать прогоны.

## 6. Что фиксировать в отчёте

Скрипт уже включает:

- `url` и `ts` (время прогона);
- `hostCount` — какой домен (vk.ru/vk.com) реально встречается в ссылках;
- `blocks` — количество совпадений по каждому селектору/якорю;
- `userExtraction` — примеры извлечённых username и способ их получения;
- `summary` — сводка «N из M» совпадений.

Дополнительно вручную фиксируйте:

- точный URL страницы (если отличается от `location.href`);
- признаки мобильной/десктопной вёрстки;
- любые новые классы/структуру, замеченные в DOM (если старые селекторы
  перестали срабатывать).

## 7. Порядок действий перед правкой расширения

1. Собрать отчёты по всем нужным типам страниц (см. п. 3).
2. Сравнить, какие механизмы из `vkcom.js` «живые», какие «мёртвые».
3. Отдельно проверить, на какой домен (vk.ru/vk.com) указывают ссылки.
4. Только после анализа вносить изменения в `vkcom.js` и `manifest.json`
   (по отдельному запросу).

## 8. Этапы: диагностика без расширения → проверка после правок

Тестирование разделено на два самостоятельных этапа. Их не следует смешивать.

### 8.1. Этап 1 — диагностика DOM БЕЗ расширения

- Скрипт `test/vk_dom_diagnostic.js` самодостаточен: это обычный JS в консоли
  страницы, он только читает DOM (querySelectorAll и т.п.), ничего не меняет и
  ничего не отправляет.
- Расширение НЕ нужно и НЕ должно быть загружено на этом этапе.
- Текущее расширение зашито на `vk.com`, поэтому на `vk.ru` оно всё равно не
  сработает — грузить его для диагностики бессмысленно.
- Задача этапа — собрать отчёты о реальной вёрстке (см. п. 3–6) до любых правок.

### 8.2. Этап 2 — проверка работы расширения ПОСЛЕ правок

- Выполняется только после внесения правок под `vk.ru`
  (`manifest.json` `matches`, `vkcom.js` `urls`/регэкспы/сборка url).
- Тут уже загружается распакованное расширение в чистом профиле
  (вручную или через `--load-extension`, см. п. 2).
- Задача — убедиться, что меню, раскраска, бейджи и сохранение событий
  реально работают на живой странице vk.ru.

### 8.3. Условия и ограничения по объёму работ

- **Только Edge — только VK.** Тестирование и дальнейшая разработка ведутся
  только в Edge и только по порталу VK (vk.ru).
- **Смена структуры базы.** Отказ от модели «психологии манипуляций» —
  открывается логика маркетинга. Структура БД и смысловая модель персоны/события
  пересматриваются (детализация — отдельной задачей).
- **Ревизия ЖЖ, RUTUBE.** Проводится ревизия поддержки LiveJournal и RUTUBE;
  остальные порталы (cont.ws, YouTube, Habr, aftershock) готовятся к удалению.
- **Дальнейшее подключение:** в перспективе из группы VK подключаются
  OK (Одноклассники) и Dzen.
